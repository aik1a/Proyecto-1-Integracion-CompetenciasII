# Pruebas, evidencias y entrega

## Calidad objetivo

El proyecto debe funcionar, ser legible, reproducible y explicable por estudiantes de segundo año. No se busca calidad empresarial ni cobertura total.

## Pruebas mínimas

- unitarias para horarios, marcaciones y filtros;
- integración básica entre aplicación y MySQL;
- comprobación del CRUD de usuarios;
- comprobación de CA-01, RE-01, RE-02, RE-03 y AP-01;
- recorrido manual de las pantallas necesarias para la demostración.

No se requieren pruebas de carga, múltiples navegadores, infraestructura externa, seguridad avanzada ni una suite E2E extensa.

## Registro por caso

| Campo | Contenido |
| --- | --- |
| ID | Identificador breve |
| Requerimiento | Requerimiento oficial relacionado |
| Entrada | Datos utilizados |
| Resultado esperado | Comportamiento definido |
| Resultado real | Resultado observado |
| Estado | Aprobado o Fallido |
| Evidencia | Salida o captura necesaria |

## Evidencia mínima

- comandos de instalación y ejecución;
- resultado real de las pruebas automatizadas;
- capturas estrictamente necesarias para las pautas;
- script de creación de la base de datos;
- datos de demostración sin información personal real;
- limitaciones y pruebas no realizadas declaradas expresamente.

## Condición de cierre

Una fase termina cuando funciona su alcance, pasan sus pruebas obligatorias, la evidencia es reproducible y no quedan defectos relevantes para la siguiente fase. Una mejora opcional no bloquea el cierre y no se implementa dentro del MVP.

## Entrega final

La entrega reúne el MVP operativo, código asociado a los requerimientos, script de base de datos, plan y evidencias de pruebas, evidencias de avances 1.2 a 1.5, presentación e informe de empleabilidad solicitado.
